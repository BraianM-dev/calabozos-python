1. Para qué sirve este recurso

Calabozos & Python es una campaña RPG educativa para practicar los fundamentos de Python de forma progresiva: print, variables (int, float, booleanos), condicionales, bucles, listas, diccionarios, funciones, random y try/except.

Los estudiantes avanzan por un mapa de calabozos, resuelven misiones narrativas y reciben ayuda de Pip el Ayudante, un NPC que explica conceptos y analiza código incompleto sin regalar la solución completa.

  • Validación real del código (intérprete Python en el navegador).
  • Pistas progresivas y checklist de diagnóstico.
  • Interacciones variadas: programar, completar, depurar, ordenar, predecir, explicar, comparar soluciones, elegir casos de prueba y completar seguimientos.
  • Los bloques se pueden arrastrar o mover con botones y teclado.
  • Persistencia local, sello rápido y exportación/importación completa de la partida.
  • Exportación de hoja de avance en PDF A4 de una sola página.
  • Se publica como sitio estático en GitHub Pages; Skulpt y CodeMirror se incluyen localmente y no requieren una CDN.

No es obligatorio completar todo el mapa. Podés detenerte después de condicionales o listas según el programa de tu curso.

3. Cómo usarlo en el aula

Secuencia recomendada

  1. Presentá el recurso (mapa, Pip, idea de “misiones”).
  2. Cada estudiante escribe nombre y apellido y elige una clase.
  3. Avanzan por el mapa en orden (los temas se desbloquean progresivamente).
  4. Si se traban: abren a Pip, preguntan el concepto o mandan un fragmento de código.
  5. Al cerrar un tema, anotan el sello o exportan la hoja de avance.

Roles posibles del docente

  • Facilitador: circulás, mirás checklists, pedís que le pregunten a Pip antes de intervenir.
  • Modelador: resolvés en vivo un sub-nivel mostrando el razonamiento (sin pegar la solución).
  • Evaluador: usás la hoja PDF + el sello de progreso como evidencia.
Sugerencia: pedí que, antes de pedir ayuda a vos, le escriban a Pip “qué me falta” o “qué es una variable”. Eso refuerza la autonomía y el lenguaje técnico.

Carpeta niveles/

La carpeta niveles/ sirve para páginas opcionales por tema, pensadas para embeber en un LMS o aula virtual un solo bloque del recurso (por ejemplo solo print o solo input), sin obligar a cargar todo el mapa de una vez.

Cada archivo de esa carpeta puede ser una mini página con consignas + un iframe a juego.html. El progreso sigue guardándose en el navegador del estudiante.

Ver niveles/README.md y el ejemplo niveles/ejemplo-print.html.

4. Embeber con iframes

Podés integrar el juego en un aula virtual (Moodle, Classroom con HTML, sitio institucional, etc.) sin salir de la plataforma.

Una misión concreta

Para proyectar o asignar una misión puntual, usá por ejemplo juego.html?nivel=input-5. Para repetir la introducción, agregá ?bienvenida=1.

Un solo tema

Usá ?tema=print, ?tema=input, ?tema=variables, etc. El dominio se calcula únicamente sobre las misiones de ese bloque.

Consejos prácticos

  • Usá height de al menos 700–900 px para que el editor y el mapa se vean cómodos.
  • En móviles el layout se adapta, pero la experiencia de código es mejor en notebook o PC.
  • El progreso se guarda en el navegador del estudiante (localStorage), no en el servidor.
  • Si el LMS bloquea iframes de otros dominios, subí el recurso al mismo dominio o usá la versión local.

5. Accesibilidad y DUA

El panel ♿ permite ajustar:

OpciónPara quién ayuda
Tamaño de letraBaja visión, fatiga visual, proyector
Tema claro / oscuroPreferencia y condiciones de luz del aula
Contraste altoNecesidades de contraste elevado
Modo dislexiaLectura más cómoda (fuente alternativa)
Reducir movimientoEpilepsia fotosensible, vértigo, distracción

En términos de Diseño Universal para el Aprendizaje:

  • Representación: teoría + ejemplos + narrativa RPG + Pip oral/escrito.
  • Acción y expresión: código libre, completar, ordenar con arrastre o botones, predicciones, checklist, PDF y reintentos.
  • Engagement: clases de personaje, inventario, misiones, feedback inmediato, ayuda sin spoiler.

Gamificación responsable: las animaciones y los reconocimientos aparecen por avances verificables. Se evita el premio aleatorio, la racha obligatoria y cualquier mecánica de permanencia compulsiva. El estudiante puede desactivar todo movimiento.

6. Evaluación y evidencia

  • Hoja de avance PDF: el estudiante la descarga al final o al cerrar un bloque de temas.
  • Guardado automático: conserva el progreso y los borradores en este navegador. La ficha PDF contiene el sello para recuperar temas completos con el mismo nombre; no sustituye todos los datos locales.
  • Sello de progreso: código tipo PY-XXX-XXX-XXX que resume temas completados (útil para recuperación).
  • Observación en clase: mirar el checklist (qué requisitos fallan) y si usa a Pip de forma autónoma.
  • Dominio: el juego muestra el porcentaje de misiones completadas. No es una nota académica.

Sugerencia de rúbrica simple: completitud de sub-niveles + calidad de las preguntas a Pip + capacidad de corregir con las pistas (sin copiar soluciones).

7. Rol de Pip el Ayudante

Pip puede:

  • Explicar conceptos: variable, algoritmo, print, input, int, float, condicional, lista, diccionario, función, bucle, indentación, try/except…
  • Analizar fragmentos incompletos (print, def, comillas o paréntesis sin cerrar).
  • Señalar el primer requisito del checklist que falla y dar una pista concreta.
  • Resumir la consigna, proponer el primer paso, explicar el último error y sugerir casos de prueba.
  • Explicar por qué los identificadores deben evitar ñ y tildes en esta consola.
  • Guiar en hasta tres niveles: pregunta socrática, pista enfocada y estructura general con huecos.
  • Explicar una línea concreta, acompañar una traza y revisar nombres, repeticiones y claridad.
  • Producir una devolución estructurada: propósito, criterios cumplidos, primera dificultad y prueba recomendada.

Pip no es una IA generativa ni reemplaza la evaluación docente. No entrega una respuesta completa para copiar: sus preguntas, pistas y plantillas buscan que el estudiante explique, pruebe y corrija.

El avatar original de profesor-búho funciona como señal visual del acompañamiento. Sus reacciones indican que Pip está explicando o celebrando un aprendizaje; no alteran la evaluación ni entregan premios al azar.

8. Problemas frecuentes

SituaciónQué probar
No corre el código / no hay salida Comprobar que se haya subido completa la carpeta assets/vendor. Abrir la consola del juego y probar el editor básico.
Se perdió el progreso Usar el sello de recuperación en la pantalla inicial (mismo nombre y apellido).
El editor no se ve bien Hay fallback a textarea si CodeMirror no carga.
La consola falla con ñ o tildes Conservarlas en textos y comentarios, pero escribir identificadores compatibles: dano, numero, pocion.
Animaciones molestan Panel ♿ → Reducir movimiento.
Quiero solo un tema Podés pedir que avancen hasta ese tema y se detengan; el mapa es lineal.
